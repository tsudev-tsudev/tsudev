### 2.1 ✅ Xoay `NEWSROOM_TICK_TOKEN` — ĐÃ LÀM XONG 21/08 (phiên 12)

**Kết quả:** token cũ `mB50…` (lộ scrollback phiên 9) đã vô hiệu. Token mới đặt
đồng thời ở **ba** chỗ: Render `tsudev-backend`, Worker `tsudev-newsroom-cron`,
và `backup/production-env-2026-08-19.txt` (hai dòng 36+56). Nghiệm thu: curl
Render trực tiếp **202**, `npm run newsroom:check` AgentRun **237 → 240**.

**Bài học trả giá (đưa vào họ §0.7):** token base64 (`openssl rand -base64`) kết
thúc bằng `=` và chứa `-`/`_` — form web của Render **cắt/thêm ký tự khi dán**,
gây 401 câm mà nhìn y hệt "đã đổi rồi". Lần đầu xoay thất bại đúng vì thế. **Dùng
`openssl rand -hex 32`** (64 ký tự `0-9a-f`, không dấu đặc biệt, không padding) —
dán không thể sai. Và luôn **tách bạch chẩn đoán**: curl thẳng Render để biết đầu
Render đúng chưa, TRƯỚC khi kết luận cron lệch — `newsroom:check` gửi token
backup nên 401 của nó chỉ nói "backup ≠ Render", không nói gì về cron.

Quy trình bốn bước bên dưới GIỮ LẠI làm tham chiếu cho lần xoay sau (bước 1 đổi
sang hex).

**Vì sao token bản thân không khẩn:** token KHÔNG vào git, chỉ từng in ra terminal
ở phiên 9. Xoay là phòng ngừa.

**Cơ chế** (đọc trước khi làm): backend (Render) so khớp token bằng **chuỗi thô**
qua header `x-newsroom-token` (`services/newsroom-service/src/index.ts:73`). Worker
cron `tsudev-newsroom-cron` gửi header đó lấy từ secret cùng tên
(`infrastructure/newsroom-cron/src/index.ts:76`). **Không có cơ chế hai-token** —
lệch đầu nào cũng làm mỗi tick trả 401 CÂM (toà soạn đứng yên, không gì đỏ lên).

**Cửa sổ an toàn:** tick THẬT chạy **mỗi giờ ở phút 7** (cron `7 0-17,23 * * *`).
Nhịp `*/5` chỉ giữ ấm Render, không gọi việc. ⇒ Đổi cả hai đầu **trong cùng một
giờ, giữa hai lượt phút-7** thì không mất lượt việc nào.

**Các bước:**

1. **Sinh token mới** — DÙNG HEX, không base64 (xem bài học trên):

   ```bash
   openssl rand -hex 32
   ```

   Ghi vào backup NGAY (cả hai dòng) để có MỘT nguồn chuẩn, rồi copy từ đó:
   `sed -i "s|^NEWSROOM_TICK_TOKEN=.*|NEWSROOM_TICK_TOKEN=<token>|g" backup/production-env-2026-08-19.txt`.
   Dán CÙNG chuỗi đó ở cả hai bước dưới, TRÙNG NGUYÊN VĂN. **Đừng chạy lại
   `openssl`** — mỗi lần chạy ra giá trị khác.

2. **Đầu Render** (backend đọc token) — Dashboard Render → service
   **`tsudev-backend`** (tên service trên Render; nó chạy code workspace
   `backend-bundle` — `dockerCommand: node services/backend-bundle/dist/index.js`,
   `render.yaml:22,30`) → **Environment** → sửa biến `NEWSROOM_TICK_TOKEN` = token
   mới → **Save**. Render tự restart service.

   > Ở dev bốn cổng thì biến này nằm ở `newsroom-service`; production gộp tất cả
   > vào MỘT service Render tên `tsudev-backend` (CLAUDE.md, mục "Production KHÔNG
   > chạy bốn tiến trình"). `backend-bundle` là tên MÃ NGUỒN, không phải tên
   > service — nó không hiện trên dashboard.

3. **Đầu Worker cron** (bên gọi tick) — trên máy dev:

   ```bash
   npm run cron:secret
   # = wrangler secret put NEWSROOM_TICK_TOKEN --config infrastructure/newsroom-cron/wrangler.jsonc
   ```

   Lệnh hỏi giá trị → dán CHÍNH token đã dán ở bước 2. (Cần đã `wrangler login`.)

4. **Nghiệm thu ngay** — đừng chờ nhịp cron tự nhiên:
   ```bash
   npm run newsroom:check
   ```
   Phải thấy `tick → HTTP=202` và AgentRun TĂNG. Nếu **401** → hai đầu lệch nhau,
   kiểm lại đã dán đúng cùng một chuỗi ở cả bước 2 và 3.

> Nếu muốn zero-downtime tuyệt đối sau này: sửa `tickGate` chấp nhận cả token cũ
> lẫn mới (đọc từ `NEWSROOM_TICK_TOKEN` + `NEWSROOM_TICK_TOKEN_OLD`), xoay xong
> mới gỡ biến cũ. Chưa cần cho lần này.
